## 2. 评估性能（S-1、S-3）

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 同进程内的 L2 评估 | 226 秒 | 19–23 秒 |
| 只到 L1 的评估 | 40–70 秒 | 9–12 秒 |
| 本机常驻 worker，CLI 端到端 | — | L1 11–17 秒，L2 19–34 秒 |
| 平台 worker 的计算时间 | — | L1 2.6–10 秒，L2 22–32 秒；经 taijifs 往返额外 10–20 秒 |

程序化搜索实际吞吐约 15–20 个 trial / 分钟（本机 2 个 worker 加平台 8 个），是试点阶段（25–30 个 / 小时）的约 30–40 倍。

## 3. 程序化搜索（S-7）

`prog-evolve-001`：中证 800，5 日周期，量价、成交量、换手、估值四个领域，进化式搜索 400 个 trial。

- 结果：400 个都通过 L0，118 个通过 L1，54 个通过 L2，通过 L3 的为 0，没有生成 HoldoutRequest。
- L3 门槛：在 400 个 trial、ICIR 方差 0.068 的条件下，纯噪声能达到的最大 ICIR 期望值为 0.78，没有候选超过。进化式搜索会产生大量相近变体和正负号翻转的版本，ICIR 方差因此被推高，门槛也随之变高。
- 这说明独立记账加 L3 能挡住盲目大规模搜索的假阳性。另一方面，程序化搜索更适合作为提供候选的来源，而不是直接产出结论。

| 超额最大回撤 | −9.1% |

ridge 版本：IC 0.077（不如等权合成），信息比率 0.37。第一版组合代码没有施加市值约束，主动市值暴露达到 −1.14 个标准差，当时信息比率 0.93 的结果主要来自小盘偏向，这组数字已经作废。修正后单名约束改为主动权重口径（13 §4.4）。

## 6. 实施中修复的问题

- 本机与平台并发访问时的数据库迁移竞争、因子编号分配竞争。
- 平台上可编辑安装一直指向第一次上传的代码。
- 桥接进程的心跳误判、转发慢、重启后遗留的孤儿任务。
- 库因子缓存非原子写入。
- 中性化用批量伪逆时，BLAS 多线程在小矩阵上严重抢占。
- 周期不一致的提交被误判为重复提交。
- 结题时 holdout 读取预算为 0 导致失败。
- 事件合并时股票代码列的类型不一致。
- `search run` 命令没有注册到 CLI（已补上 CLI 层面的测试）。
