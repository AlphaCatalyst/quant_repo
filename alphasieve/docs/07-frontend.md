# 07 · 前端

## 1. 定位

前端是**审查台**，不是操作台。agent 通过 CLI 工作，前端不替 agent 点按钮；前端要让人低成本地做三件事：

1. **看清进展**：agent 在做什么、筛到哪一层、花了多少预算、为什么没进展。
2. **做出决定**：批准 holdout、评审候选、批准进入 paper、回复 agent 请求。
3. **引导研究**：创建 campaign、给 agent 下指令、在因子和报告上写评论。

## 2. 设计原则

| 原则 | 落实 |
|---|---|
| 证据等级永远可见 | 每个指标旁都有 `DEV` / `HOLDOUT` / `FRESH` 标签和固定配色；不同等级的指标不混在同一个数字里 |
| 搜索强度永远可见 | 展示任何“最佳结果”时，同时显示它是从多少次 trial 中挑出来的，以及当前 DSR 门槛 |
| 失败与成功同等展示 | 漏斗每一层都能点进去看被淘汰的候选和原因；证伪记录有独立入口 |
| 决定必须有理由 | 所有审批表单的理由字段必填；决定时锁定证据快照 |
| 不泄漏给 agent | 带 HOLDOUT / FRESH 信息的区域标注“不可共享给 agent”；给 agent 下指令的输入框会检测并阻止引用这些区域的内容 |
| 收益不是首屏指标 | 首屏是漏斗、预算、待办；收益曲线只出现在策略与前瞻页面，并与基准并列 |

## 3. 信息架构

```text

  ├─ 列表
  └─ 详情：进展 | Agent 活动 | 候选 | 搜索强度 | 预算 | 报告 | 时间线

  ├─ 列表（按状态 / 族 / campaign 筛选）
  └─ 详情：定义 | 证据 | 边际贡献 | 相关性 | 谱系 | trial 历史 | 评审

  └─ 覆盖矩阵（数据域 × 变换形态 × 时间尺度）、SearchSpace 版本

```

顶部导航常驻：审批中心角标（待办数）、全局预算用量、正在运行的 agent 会话数。

### 4.2 Campaign 详情

标签页：

- **进展**：筛选漏斗（每层可点开看候选与淘汰原因分布）、停止条件进度条（trial、turn、费用、时长、无改进轮数）、campaign 状态与下一步。
- **Agent 活动**：实时 turn 流（当前假设、工具调用、评估结果卡片），历史 turn 可回放；右侧是指令面板（下指令、查看已消费指令）。
- **候选**：本 campaign 的全部候选表格，列：表达式、族、状态、dev RankIC / ICIR、与库最大相关、trial 数、提交 turn。
- **搜索强度**：横轴为累计 trial 数，纵轴为指标；两条线：本 campaign 最佳 dev ICIR（或 Sharpe）与 DSR 显著性门槛。门槛线高于最佳线时，任何“最佳结果”都不可信。
- **预算**：各类预算的消耗曲线与预测耗尽时间。
- **报告**：agent 的 turn 报告与阶段报告，human 可评论。
- **时间线**：状态变化、指令、审批、告警按时间排列。

### 4.3 因子详情

- **定义**：表达式（语法高亮 + 表达式树视图）、假设、族、参数来源（默认 / 邻域救援）、提交者与 turn。
- **证据**：按证据等级分栏的指标表（DEV | HOLDOUT | FRESH），每栏标注区间与样本量；分年度 RankIC 柱状图、分组收益图、四个子窗口对比。
- **边际贡献**：参考模型组上的提升，逐模型列出。
- **相关性**：与因子库成员的相关性排行、所在族的聚类位置。
- **谱系**：从哪个假设、哪个父版本演化而来；后续版本。
- **trial 历史**：该因子所有版本的 trial 记录。
- **评审**：Review Packet 与决定记录、评论。

### 4.4 审批中心

- 统一列表，按类型筛选，显示提交时间、等待时长、关联 campaign。
- 每一项点开进入对应的决定页（HoldoutRequest 详情 / Review Packet / Agent 请求详情）。
- 决定后自动推进状态机，并在 campaign 时间线留痕。

### 4.6 其他页面

- **搜索空间**：覆盖矩阵热力图，每格显示尝试数 / L2 通过数 / 入库数 / 禁区标记，可按时间范围与 campaign 筛选；点格子进入该格的候选列表；创建 campaign 时在此选择格子范围（定义见 [11-factor-search-space.md](11-factor-search-space.md)）。
- **Ledger**：只读表格，按 campaign、因子、证据等级、gate 结果、创建者筛选；可导出 CSV；显示哈希链校验状态。
- **策略**（M6）：StrategySpec 列表；回测净值与基准、超额、跟踪误差、信息比率、换手、行业偏离。
- **前瞻**（M7）：cohort 列表；每个 cohort 自锁定日以来的累计超额；机器 / 人 / AI 信号池对比；regime 信任门状态。
- **记忆**：成功模板、禁区、洞察、证伪记录；每条可追溯来源 trial。
- **数据**：区间边界、最新日期、覆盖率热力图、质量检查结果。
- **设置**：默认预算与调度参数（可编辑）、gate policy（只读展示当前版本与历史）、agent 运行配置、用户。

## 5. 视觉约定

| 元素 | 约定 |
|---|---|
| 证据等级 | DEV 灰蓝、HOLDOUT 琥珀、FRESH 绿色；徽章 + 左边框色条 |
| 状态徽章 | 失败类红、进行中蓝、待人工紫、通过类绿、终态灰 |
| 数字 | 保留有效位数；IC 3 位小数；收益为年化百分比并注明是否扣成本 |
| 图表 | ECharts 统一主题；所有收益图都叠加基准 |
| 语言 | 界面中文，代码与接口字段英文 |

## 6. 技术方案

| 项 | 选型 |
|---|---|
| 框架 | React 18 + TypeScript + Vite |
| 路由与数据 | TanStack Router、TanStack Query（缓存、轮询、SSE 失效刷新） |
| UI | Tailwind CSS + shadcn/ui；表格用 TanStack Table |
| 图表 | ECharts（漏斗、折线、热力图、树图） |
| 表达式 | 语法高亮组件 + 自绘表达式树 |
| 实时 | EventSource 订阅 `/api/v1/events`，按事件类型让对应 query 失效 |
| 类型 | 由 FastAPI OpenAPI 生成 TypeScript 类型（`openapi-typescript`） |
| 测试 | Vitest + Testing Library；关键流程用 Playwright |

目录：

```text
web/
  src/
    routes/          页面（与信息架构一一对应）
    components/      通用组件：EvidenceBadge、StateBadge、Funnel、SearchIntensityChart、
                     BudgetMeter、TurnStream、ExpressionView、MetricTable、DecisionForm
    api/             生成的类型与请求封装
    lib/             SSE、格式化、主题
```

部署：`alphasieve serve` 同时托管构建后的静态文件，单机一个端口即可访问。
