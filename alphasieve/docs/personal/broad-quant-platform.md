# 27 · 广义量化分析平台：面向 50 万–1000 万个人持仓的 agent 能力

状态：构想，未实现，未立项。日期 2026-10-03。只交付本文，不改代码、配置或预算，不运行 trial，不读取 holdout/fresh。本文把 AlphaSieve 从"A 股日频因子研究系统"扩展为"个人持仓的广义量化分析平台"，列出可以结合 agent 的能力、各自的验证方式和优先级。是否立项及范围由 human 决定，立项后记入 [decisions.md](../overview/decisions.md)。资金体量相关的约束沿用 [personal-account.md](personal-account.md)，本文把范围放宽到 50 万–1000 万。文中收益区间是粗略经验值，不是验收结论，也不构成投资建议。

## 1. 为什么要扩展

- [personal-account.md](personal-account.md) 的分散化系统策略，合理预期是夏普 1.0–1.5、年化 10%–20%。这是稳健的底仓，但收益上限不高。
- 收益上限更高的是**论点驱动的集中研究**：押注少数标的的一个核心变量，看对时一年有几十个百分点到翻倍，看错时回撤 40%–60%。上限更高的代价是方差更大，不是白拿的收益。
- 个人在这类研究上有结构性优势：容量不是问题，可以持有 1–3 年，没有赎回压力，也愿意做机构研究员嫌麻烦的细节核对。
- LLM agent 在这类工作上的适配度高于挖因子：检索与阅读公告、研报、纪要，搭建估值模型，逐项核对参数，对抗式复核。
- 这类研究最大的风险是事后叙事和 agent 编造数据。AlphaSieve 已有的纪律可以直接迁移：只追加的记账、证据分级、预注册、前瞻结算、人做决定。

## 2. 样例：猪周期估值推演的辩证复核

外部样例：[AlphaNotes · 猪周期估值推演的辩证复核](https://alphacatalyst.github.io/AlphaNotes/reports/hog-cycle/analysis.html)（2026-09-16，2026-10-03 补记）。标的为牧原股份、东瑞股份。它的方法就是本平台"论点研究"要固化的流程：

| 步骤 | 报告中的做法 |
|---|---|
| 还原论证结构 | 周期观 → 参数（猪价、完全成本、出栏量、均重、PE）→ 估值 |
| 逐项核对参数 | 每个数字追到公告、投资者关系记录、期货报价；"1 亿头出栏"在公司所有公开文件中查无出处 |
| 证据分级 | A 类公告与统计原文；B 类管理层口头表述；C 类媒体、券商测算与本报告推演；D 类明确未找到、不得编造 |
| 用历史检验经验规律 | "低点越低、下轮高点越高"与历史数据方向相反；决定高点的是能繁母猪去化幅度 |
| 反推市场隐含预期 | 把卖方 2027 年参数（猪价 14、成本 11.2）代入原公式得 41.99 元，现价 42.59 元：股价已反映一致预期，只有猪价显著高于 14 元才有超额 |
| 敏感度与情景矩阵 | 猪价对估值的影响（−76.9 元）远大于出栏（−25.4 元）和成本（−19.2 元） |
| 对抗式复核与修正 | 吸收原作者与外部视频的反驳后，把上行期成本区间从 12.8–14.2 元下修为 12.0–13.5 元；给原文 8 条疑点打分 |
| 口径警告 | 猪价至少五套权威序列，同日差异 0.3–1.0 元/kg；跨期比较必须锁定口径 |

样例说明两点：一是大多数深度研究的结论会是"市场基本是对的"，超额来自少数确实看得更准的时候；二是这份报告缺少的是**可结算的预测和事后校准**，平台要补的正是这一环。

## 3. 资金分档

| 档位 | 能做的 | 主要约束 |
|---|---|---|
| 50 万–100 万 | 两融、股指期货、期权、科创板的资产门槛刚好够；ETF 跨资产配置、可转债、15–30 只股票、1–2 个论点仓位 | 最低佣金 5 元影响更大，需"免五"；一手 IC / IM 名义本金约 100 万以上，无法对冲；10% 的收益只有 5 万–10 万元，研究时间要算性价比 |
| 100 万–500 万 | [personal-account.md](personal-account.md) 的全部方向 | 对冲只能 1–4 手，颗粒度粗 |
| 500 万–1000 万 | 多策略并行；股指期货对冲 4–8 手；期权策略更完整；港股通 | 冲击成本仍可忽略；单一论点仓位的绝对金额变大，仓位纪律更重要 |

推荐结构是"核心加卫星"：核心仓位约 60%–80% 放系统化组合（多因子选股、可转债、ETF 跨资产配置），目标夏普约 1.0；卫星仓位约 20%–40% 放论点驱动的集中仓位，单个论点设上限（例如 10%–15%）。整体上限主要由卫星部分决定：一年能找到几个真正有优势的论点（现实中约 2–5 个），以及仓位纪律守得住多少。长期年化 20%–30% 已是很顶尖的个人水平。

## 4. 平台分层

```text
数据层     行情、财报、事件（已有）＋ 行业基本面、期货曲线、公告 / 纪要 / 研报文本库、持仓与成交
对象层     Factor、Mandate / Strategy（已有）＋ Thesis、Forecast、Event、Holding、Decision
agent 层   Miner（已有）＋ Researcher、Reviewer、Monitor、Portfolio Analyst、Data Engineer
记账层     trial ledger（已有）＋ forecast ledger、decision journal，均只追加
交互层     前端看板、审批中心（已有）＋ 论点页、持仓体检、每周简报、证伪告警
执行       人工下单；接入 QMT / miniQMT / PTrade 另行决定
```

不变的原则：

1. agent 只提案和整理证据，确定性后端负责计算（估值公式、风险暴露、结算），人做投资决定。
2. 每个数字带出处和可信度等级（A/B/C/D），找不到就写"未找到"，关键数字交叉验算。
3. 预测与决策在作出时写入只追加的账本，带时间戳和当时可得的数据快照，事后不能改写。
4. 系统化研究继续遵守 holdout / fresh 隔离；论点研究不能回测，验证靠前瞻结算和校准度。
5. 不自动下单；只服务本人持仓，不对外提供荐股或代客理财（需要投资咨询牌照）。

## 5. 可以结合 agent 的能力

按方向分组。"验证方式"一栏说明怎样防止事后叙事或编造；"复用"指能用上 AlphaSieve 现有的哪些部分。

### 5.1 论点研究（卫星仓位的核心）

| 能力 | agent 做什么 | 验证方式 | 复用 |
|---|---|---|---|
| 论点深度研究 | 还原论证结构，逐项核对参数并分级，搭建估值公式与情景矩阵，反推市场隐含预期 | 每个参数带出处；估值公式由后端计算；输出"我方估计 vs 市场隐含值"的分歧点 | 研报文本（westock 约 95 万篇）、财报与事件数据 |
| 对抗式复核 | 独立 Reviewer 会话专门找错：口径混用、时点错配、自我批评是否成立 | 与 Researcher 不共享记忆；意见附在论点上，只供人参考 | [agent-harness.md](../agent/agent-harness.md) §8 的 Reviewer 设计 |
| 可结算预测 | 把论点拆成可结算命题，例如"LH2709 结算价 > 15 元，概率 40%" | 写入 forecast ledger；到期由后端按预先指定的数据源结算；长期统计 Brier 分数与校准曲线 | ledger 的哈希链与只追加机制；[forward-paper.md](../mandates/forward-paper.md) 的前瞻结算 |
| 证伪条件监控 | 跟踪论点的关键变量，触发预注册的证伪条件时告警，例如"上行期玉米涨幅超过一成" | 证伪条件在建仓前登记；告警后由人决定是否退出 | 事件流与通知 |
| 行业研究模板 | 按行业沉淀分析框架：周期股（供给去化 → 价格 → 成本 → 盈利 → 隐含预期）、消费、科技、金融 | 模板版本化；同一模板下的论点可横向比较命中率 | SearchSpace 的版本化思路 |

周期股最适合起步：生猪、航运、锂、煤、化工价差、有色。它们的核心变量往往有期货价格，可以直接读出市场隐含预期，也可以用期货或期权更直接地表达观点。

### 5.2 信息与事件处理

| 能力 | agent 做什么 | 验证方式 | 复用 |
|---|---|---|---|
| 公告解析 | 结构化回购、增持、减持、解禁、股权激励、并购重组、业绩预告 | 输出带原文定位；按公告时间 PIT 对齐 | 事件 panel（`data/events.py`） |
| 纪要与口径变化检测 | 对比管理层在投资者关系记录、业绩会中的表述，标出口径变化（如"成长不一定是出栏量增长"） | 引用原文与日期；变化本身不构成结论 | — |
| 卖方观点审计 | 解析研报中的盈利预测与评级，追踪分析师与券商的历史准确率和修正方向 | 只用发布时可得的预测；准确率按事后实际值结算 | westock 研报；可派生 `wr_*` 因子进入因子 campaign |
| 文本事件因子（E5） | 从文本抽取结构化事件特征，交给系统化研究 | 带发布时间戳；按事件驱动规则走 L0–L4 | [factor-search-space.md](../research/factor-search-space.md) §2 |
| 政策与宏观解读 | 摘要政策文件、宏观数据发布，关联到受影响的行业和持仓 | 只做整理和关联，不自动生成交易信号 | — |

### 5.3 持仓风控与排雷

| 能力 | agent 做什么 | 验证方式 | 复用 |
|---|---|---|---|
| 财报排雷 | 检查应收与存货异常、利润与现金流背离、商誉、关联交易、审计意见、大股东质押 | 规则指标由后端计算；agent 写解读并标出处 | westock 全报表、通达信财务包（[data-vendors.md](../data/data-vendors.md) §7.7） |
| 持仓体检 | 汇总行业与风格暴露、集中度、相关性、压力情景（如"小盘风格踩踏重演"） | 暴露与压力测试由后端计算 | [risk-model.md](../mandates/risk-model.md) 的风格暴露设计 |
| 每周持仓简报 | 持仓变化、论点状态、证伪告警、待办决定 | 只引用已记录的数据与论点 | 前端"待你决定" |
| 现金与成本管理 | 提示季末逆回购、货基与短债配置、税费与佣金优化 | 收益率与费用由后端计算 | — |

### 5.4 特殊情况与小容量机会

| 能力 | agent 做什么 | 验证方式 | 复用 |
|---|---|---|---|
| 可转债条款博弈 | 解析下修、回售、强赎条款与公告，计算各情景收益 | 条款引用原文；收益情景由后端计算 | 需新增可转债数据 |
| 折溢价与套利扫描 | LOF / ETF 折溢价、AH 溢价、要约收购与私有化、REITs | 扫描规则固定；agent 只解释机会和风险 | — |
| 事件日历 | 指数调样、分红除权、解禁、股东大会 | 日期来自公告与交易所 | — |

### 5.5 系统化研究（核心仓位，已有）

| 能力 | agent 做什么 | 验证方式 |
|---|---|---|
| 因子挖掘 | 现有 Miner 循环 | L0–L4、trial ledger、搜索折扣（已实现） |
| 研究复现 | 读券商金工报告或学术论文，写成预注册的因子 spec 或 TrainingTask | 预注册后按现有链路评估，复现失败也入账 |
| 个人账户 mandate | 见 [personal-account.md](personal-account.md) §5 | 策略层 trial 与 holdout 规则 |
| 新资产类型 | 可转债、跨资产 ETF、商品期货 CTA 的数据接入与回测适配 | 按 mandate 单独记预算与搜索折扣 |

### 5.6 宏观与资产配置

| 能力 | agent 做什么 | 验证方式 |
|---|---|---|
| 宏观看板 | 跟踪利率、信用、汇率、通胀、PMI、商品价格，写周度摘要 | 数据来自官方序列，锁定口径 |
| 配置建议 | 给出股、债、金、跨境 ETF 的配置区间与理由 | 配置规则预先登记；建议写入 decision journal，事后对照基准结算 |

### 5.7 决策日志与复盘

| 能力 | agent 做什么 | 验证方式 |
|---|---|---|
| 交易日志 | 每笔交易记录理由、对应论点、证伪条件、预期持有期 | 交易前写入，事后不能改写 |
| 定期复盘 | 按季度对照日志与实际结果，区分"判断错"与"运气差" | 引用当时的记录，不用事后信息重写理由 |
| 行为偏差提示 | 识别追涨、过早止盈、亏损加仓、过度交易等模式 | 统计由后端计算；agent 只提示，不替人决定 |

### 5.8 数据工程

| 能力 | agent 做什么 | 验证方式 |
|---|---|---|
| 新数据源接入 | 调研接口、写 provider、原始落盘、记录 provenance | 与已有来源交叉核对重叠期（[data-vendors.md](../data/data-vendors.md) §7.4 已按此执行） |
| 口径核对 | 同一指标多来源的口径差异与修订检测 | 差异写入数据质量报告 |

## 6. 新增对象（草案）

| 对象 | 关键字段 |
|---|---|
| `Thesis` | 标的、核心变量、论证结构、证据表（每条带出处与 A/B/C/D 等级）、估值公式与参数、市场隐含值、我方估计区间、情景矩阵、证伪条件、仓位上限、状态（研究中 / 持有 / 已证伪 / 已兑现 / 放弃） |
| `Forecast` | 命题、结算数据源与口径、截止日、概率、关联论点、登记时间与数据快照；结算后写入实际值与得分 |
| `Decision` | 时间、动作（买 / 卖 / 调仓 / 不动作）、金额、理由、关联论点与预测、当时持仓快照 |
| `Holding` | 账户、标的、数量、成本、来源（系统化组合 / 论点仓位） |
| `EventRecord` | 来源文本定位、发布时间、结构化字段、抽取版本 |

`Forecast` 与 `Decision` 写入只追加的账本，沿用 trial ledger 的哈希链；`Thesis` 可修订，但每次修订保留版本与理由。

## 7. agent 角色

| 角色 | 职责 | 不做什么 |
|---|---|---|
| Miner（已有） | 系统化因子挖掘 | 读 holdout / fresh、改评估代码 |
| Researcher | 论点研究、参数核对、估值建模、登记预测 | 下单、修改已登记的预测 |
| Reviewer | 对论点做对抗式复核 | 与 Researcher 共享记忆、改变论点状态 |
| Monitor | 跟踪关键变量、证伪条件、公告与事件，生成告警与周报 | 自行做投资决定 |
| Portfolio Analyst | 持仓体检、排雷、复盘与行为偏差提示 | 自动调仓 |
| Data Engineer | 新数据源接入与口径核对 | 绕过 provenance 记录 |

## 9. 风险与非目标

| 风险 | 处理 |
|---|---|
| agent 编造数据或引用 | 每个数字带出处与等级；关键数字交叉验算；未找到明确标注 |
| 确认偏差：研究只为支持已有持仓 | 独立 Reviewer；证伪条件在建仓前登记 |
| 事后叙事 | 预测与决策只追加；按校准度而不是按单笔盈亏评价研究质量 |
| 过度交易 | 交易日志统计换手；行为偏差提示 |
| 集中仓位的尾部风险 | 单论点仓位上限；卫星总仓位上限 |
| 合规 | 只服务本人持仓；程序化下单前完成报告；不对外提供投资建议 |

非目标：自动下单、对外荐股或代客理财、高频与超短打板、无出处的观点汇总。
