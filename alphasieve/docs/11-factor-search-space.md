# 11 · 因子搜索空间

本文回答：agent 挖因子的空间怎么给定，才能覆盖多种因子形式，同时又不让搜索变成无边界的数据窥探。

## 1. 核心思路

搜索空间不是一句“去挖因子”，而是一份版本化的 `SearchSpace` 配置，由三部分组成：

1. **表达能力分级**：候选可以用什么形式表达（公式、模板、受限程序、学习型、文本事件）。
2. **原料**：可以用哪些终端变量与派生变量、哪些算子、窗口与复杂度上限。
3. **覆盖坐标**：用“数据域 × 变换形态 × 时间尺度”三个维度给因子空间打格子，campaign 按格子分派，进展按格子统计。

每个 campaign 绑定一个 `SearchSpace` 版本；trial 记录该版本号。扩大搜索空间是人的决定，因为它直接增加多重检验的强度。

## 2. 表达能力分级

| 级别 | 形式 | 能覆盖的因子 | 约束方式 | 引入阶段 |
|---|---|---|---|---|
| E1 公式 | DSL 表达式（见 [04-research-core.md](04-research-core.md) §2） | 量价、估值、财务比率及其时序/截面变换、组内相对 | 语法白名单，前视在构造上不可表达 | M2 |
| E2 模板 | 带槽位的因子模板 + 参数 | 学术异象的标准形式（残差动量、特质波动、Amihud 非流动性、盈余惊喜等） | 模板由系统维护，agent 只填槽位与参数 | M2 后期 |
| E3 受限程序 | Python 函数 `compute(view) -> Series`，在沙箱中执行 | 条件逻辑、事件窗口、滚动回归、分段规则、多步计算等 DSL 难以表达的形式 | PIT 数据视图（只暴露截至 t 的数据）、静态检查、截断不变性测试、资源上限 | M4 后 |
| E4 学习型 | walk-forward 训练的小模型输出分数 | 非线性组合、交互项 | 属于模型设计循环，按联合优化规则执行 | M8 |
| E5 文本事件 | LLM 从公告、研报抽取的结构化事件特征 | 业绩预告、监管处罚、回购增持、研报评级变动 | 事件带发布时间戳，按事件驱动规则验证 | M8 |

分级的意义：E1、E2 覆盖面广、验证便宜，是第一阶段主力；E3 覆盖 DSL 表达不了的形式，但需要更强的沙箱和前视检查（参考 FactorEngine 的程序级因子）；E4、E5 对应后续扩展方向。

### E3 受限程序的安全要求

- 输入是 `PITView`：只能按日期向前读取，接口上不存在“取未来值”的方法。
- 静态检查：禁止 import 白名单外的模块、禁止文件与网络访问、禁止读取全局状态。
- **截断不变性测试**：删掉 t 之后的全部数据重新计算，t 日的因子值必须不变；不满足即 L0 失败。
- 资源上限：单次计算的 CPU 时间与内存上限，超限即失败。
- 程序文本规范化后做哈希，与 E1 一样参与去重与 trial 计数。

## 3. 原料

### 3.1 终端变量

来自 panel 的白名单字段（见 [03-data.md](03-data.md) §2），按数据域分组，campaign 可以只开放其中一部分。

### 3.2 派生变量库（系统维护）

有些常用中间量用 DSL 写起来冗长且容易写错，由系统预先计算、版本化后作为终端变量开放：

| 派生变量 | 定义 |
|---|---|
| `ret_1d`、`ret_open_1d` | 收盘到收盘、开盘到开盘收益（后复权） |
| `excess_ret_1d` | 相对股票池等权收益的超额 |
| `idio_ret_1d` | 对市场与行业收益回归后的残差（滚动 60 日估计） |
| `beta_60d` | 滚动 60 日市场 beta |
| `amihud_20d` | 20 日 Amihud 非流动性 |
| `vwap_dev` | 收盘价相对 vwap 的偏离 |
| `overnight_ret`、`intraday_ret` | 隔夜与日内收益 |
| `ttm_*` | 财务 TTM 口径（按公告日 PIT） |
| `yoy_*`、`qoq_*` | 财务同比、环比（按公告日 PIT） |
| `industry_mean(x)` 口径值 | 行业均值（用于相对化） |

派生变量的定义变化会生成新版本；已有 trial 通过版本号判断是否受影响。

### 3.3 算子与限制

- 算子分类见 [04-research-core.md](04-research-core.md) §2；campaign 可以关闭部分算子（例如只允许线性算子）。
- 窗口参数：取值集合默认为 {3, 5, 10, 20, 40, 60, 120, 250}，避免连续参数带来的隐性搜索。
- 复杂度上限：节点数、深度、终端变量种类数；默认节点 ≤ 30、深度 ≤ 8、终端 ≤ 4。

### 3.4 种子库

- 预置已知因子作为种子与基线：Qlib Alpha158、国泰君安 191、WorldQuant 101、常见学术异象，以及 FactorMiner 论文公开的因子。
- 种子因子默认计入“已知因子”集合，用于相关性检查：与种子高度相关的候选不算新发现。
- agent 可以在种子上做变异（换数据域、换形态、换尺度），变异产物照常评估与计数。

## 4. 覆盖坐标

### 4.1 三个维度

| 维度 | 取值 |
|---|---|
| 数据域 | 价格、成交量额、换手与流动性、波动与风险、规模与估值、盈利质量、成长、杠杆与现金流、分红与股本、行业与关联、事件（后续）、资金流（视数据可得性） |
| 变换形态 | 水平、变化与动量、反转、波动与稳定性、偏度与尾部、相关与 beta、残差与特质、组内相对（行业 / 市值）、条件与交互、衰减加权、事件窗口 |
| 时间尺度 | 短（1–10 日）、中（20–60 日）、长（120–250 日）、财报季度 |

一个格子例如：“换手与流动性 × 反转 × 短”。格子总数约 12 × 11 × 4 ≈ 500，其中一部分组合没有意义（例如“分红 × 短期反转”），在配置中标为不可用。

### 4.2 候选如何落格

- agent 提交候选时声明主格子（数据域、形态、尺度）。
- 系统做一致性检查：从表达式推断用到的数据域与窗口，和声明不一致时给警告，并以推断结果为准记录。
- 一个候选可以有次格子（例如“估值 × 组内相对”同时带“行业”）。

### 4.3 覆盖矩阵的用途

- **进展展示**：前端按格子展示“尝试数 / L2 通过数 / 入库数 / 禁区”，一眼看出哪些区域没碰过、哪些已经饱和（见 [08-progress-and-interaction.md](08-progress-and-interaction.md)）。
- **campaign 规划**：创建 campaign 时选一组格子作为研究范围；系统可以按“未覆盖程度 × 先验价值 − 已饱和惩罚”推荐格子（思路参考 scicomp-foundry 的 coverage planner）。
- **记忆与禁区**：禁区以格子加结构模式表示，例如“换手与流动性 × 水平 × 任意尺度：与库内 F-0012 高相关”。
- **并行分派**：规模化运行时（见 [14-agent-execution.md](14-agent-execution.md)），每个并行任务分到不同格子，避免重复劳动。

## 5. SearchSpace 配置

```yaml
search_space_id: ss-ashare-daily-v1
version: 3
expressiveness: [E1, E2]            # 允许的表达能力级别
universe: zz1000
horizon_days: 5
terminals:
  domains: [price, volume, turnover_liquidity, volatility, size_value]
  derived: [ret_1d, excess_ret_1d, idio_ret_1d, amihud_20d, vwap_dev]
operators:
  disabled: [ts_corr, ts_cov]       # 可按 campaign 关闭
windows: [3, 5, 10, 20, 40, 60, 120, 250]
complexity: {max_nodes: 30, max_depth: 8, max_terminals: 4}
cells:                              # 本 campaign 的格子范围
  - {domain: turnover_liquidity, form: reversal, scale: short}
  - {domain: volatility, form: skew_tail, scale: medium}
templates: [residual_momentum, idio_vol, amihud]   # E2 可用模板
seeds: [alpha158, gtja191]
```

- agent 在 `brief.md` 中看到的是这份配置的可读版本。
- 配置变化产生新版本；同一 campaign 中途修改搜索空间需要人工确认，且修改前后的 trial 都计入同一个 DSR 计数。

## 6. 防止搜索空间变成窥探工具

- **扩大空间要付出代价**：DSR 的试验数按 campaign 累计，开放更多格子和原料只会让门槛更高。
- **离散参数**：窗口只能取预设集合，避免 agent 通过连续微调参数“拟合”历史。
- **default-first**：模板和程序的参数先用默认值，失败时只允许有限的邻域救援（见 [04-research-core.md](04-research-core.md) §4）。
- **格子内的假设先行**：program.md 要求 agent 在提交前写下假设与预期方向；方向与预期相反却“显著”的候选在 Review Packet 中高亮。
- **原料版本化**：派生变量、模板、种子的变化都有版本号，保证 trial 可复现、可归因。
