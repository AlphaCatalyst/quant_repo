# Strategy Scope：Agent Trader 兼容哪些策略

本文回答：做一个 Agent Trader 系统，应该兼容哪几类策略，以及怎么兼容。

结论：用一个统一的策略契约（Signal → Portfolio → Execution）去兼容不同策略，而不是为每类策略各做一套引擎。策略分三档：

- **核心**：截面多因子 / 模型选股，以指数增强形式落地。第一阶段只做这一类，也是 agent 唯一的自主 loop 对象。
- **兼容**：事件驱动；行业 / ETF 轮动作为配置层；择时作为风控叠加层；人工和 LLM 主观判断作为对照信号源。
- **暂不支持**：日内 / 高频、依赖做空的统计套利、期权、CTA、加密货币。

## 1. 取舍依据

| 依据 | 含义 |
|---|---|
| verifier 统计功效 | 独立观测越多，验证越可信，越适合 agent 自主 loop（\(IR \approx IC \times \sqrt{breadth}\)，见 [agent-loop-verification.md](agent-loop-verification.md) §5.2） |
| A 股约束 | T+1、涨跌停与停牌无法成交、融券受限；策略必须能在这些约束下真实成交 |
| agent 比较优势 | LLM 擅长非结构化文本与事件抽取，不擅长在低信噪比数据上凭直觉预测价格 |
| 基础设施复用 | 新策略应复用同一套数据契约、回测、gate 与 ledger |

## 2. 策略分档

| 策略类型 | 每年独立观测量级 | 定位 | agent 角色 | 支持阶段 |
|---|---|---|---|---|
| 截面多因子 / 模型选股（指数增强、Top-K 多头） | 数十万 | 核心 alpha 来源 | 自主 loop（因子，之后模型设计） | 第一阶段 |
| 事件驱动（业绩预告、公告、研报修正、指数调样、解禁） | 数千到数万 | 第二批 alpha 来源 | 从公告/研报抽取事件、提出假设；信号化后按截面方式验证 | 核心稳定后 |
| 行业 / 风格轮动、ETF 配置 | 数百 | 配置层 | 提案，门槛更严，人批准 | 后续 |
| 择时（仓位缩放、regime 信任门、回撤控制） | 十几次 | 风控叠加层，不作为 alpha 来源 | 不自主 loop | 随 paper 阶段引入 |
| 主观判断（人工选股、LLM 辩论式决策） | 视覆盖面而定 | 对照信号源，进入前瞻分池追踪 | 产出信号，不直接交易 | 随 fresh 验证引入 |
| 日内 / 高频、统计套利、期权、CTA、加密货币 | — | 暂不支持 | — | — |

### 2.1 核心：截面多因子选股（指数增强）

- A 股融券受限，多空组合难以真实执行；以沪深 300 / 中证 500 / 中证 1000 为基准做多头增强，最贴近实盘。
- 评价口径：超额收益、跟踪误差、信息比率、换手与容量；因子层仍看 IC / RankIC 与边际贡献。
- 这是 agent 自主 loop 的唯一对象（先因子，后模型设计），完整经过 L0–L5。

### 2.2 事件驱动

- LLM 的比较优势所在：把公告、研报、新闻抽取成带时间戳的结构化事件，再变成截面信号，走和因子相同的验证链路。
- 关键约束是 point-in-time：必须使用公告实际发布时间（以及盘中/盘后发布对应的可交易时点），而不是事件发生时间。
- 事件样本少于日频截面，需要按事件类型累计足够样本后再进入 L3/L4。
- 参考：`ai-hedge-fund` 的 PEAD 模型、`quant-ashare` 的公告与事件屏蔽、`TradingAgents` 的 SEC as-filed。

### 2.3 行业 / 风格轮动与 ETF 配置

- 本质是在“行业或 ETF 资产池”上的截面分数，只是资产数少（约 30 个一级行业），验证功效低。
- 定位为配置层：决定组合在行业/风格上的倾斜，或把策略暴露映射到可交易的 ETF（参考 `deepseek-harness-quant` 的 `etf/` 映射）。
- agent 可以提案，但 L3/L4 门槛更严、holdout 预算单独核算，由人批准。

### 2.4 择时：只做风控叠加

- 独立观测太少，几乎无法证明择时是 alpha。
- 定位为“是否降仓 / 今天是否交易”的门控，只作用于最终仓位，不修改选股信号：
  - regime 信任门：信任度低时不交易或降仓（参考 *When Alpha Breaks*，arXiv 2603.13252）。
  - 回撤控制、波动率目标。
- 不让 agent 在择时上自主 loop；规则变更走人工 review。

### 2.5 主观判断：对照信号源

- 人工选股、LLM 辩论式个股决策（如 `TradingAgents`）都可以接入，但只作为信号源。
- 进入前瞻分池，与机器信号并列追踪（参考 `deepseek-harness-quant` 五池：`auto_pitch` / `machine_top01` / `human_select` / `ai_select` / `niu_select`，T+1/5/20/60）。
- 价值由前瞻数据证明，不直接连到交易；LLM 决策回测应使用 blind prompt（隐去 ticker 与日期，参考 `ai-hedge-fund`）。

### 2.6 暂不支持及原因

| 类型 | 原因 |
|---|---|
| 日内 / 高频 | 数据与基础设施成本高；T+1 限制；与低频研究 OS 定位不符 |
| 统计套利 / 配对交易 | 依赖做空，A 股融券受限 |
| 期权 / 波动率 | 需要独立的定价、希腊值与保证金体系 |
| CTA / 期货、加密货币 | 市场基础设施与数据契约不同，另起一套收益低 |

## 3. 统一策略契约

所有策略都拆成三段，差异只体现在每段的具体实现上。

```text
Signal（信号）
  ├─ 截面分数：date × asset → score        选股、事件、主观判断、行业/ETF 轮动
  └─ 时序暴露：date → exposure / 开关       择时、风控叠加
Portfolio（组合构建）
  目标权重 = f(信号, 基准, 约束：行业/风格中性、个股上限、换手、容量)
Execution（执行模拟）
  T+1、涨跌停与停牌无法成交、成本与冲击、调仓频率
```

要点：

- **两种信号形态覆盖全部兼容策略**：事件驱动是带事件掩码的截面分数；轮动是行业/ETF 资产池上的截面分数；择时是时序暴露。
- **策略即配置**：一个策略 = 信号来源 + 组合构建规则 + 执行设定，写成 `StrategySpec`（见 [system-contracts.md](system-contracts.md)），类似 `ai-hedge-fund` 的 mandate YAML。
- **同一代码路径**：回测、paper、实盘只替换时钟与 broker（参考 `lumibot`、`ai-hedge-fund` 的 `run_cycle`）。
- **多策略叠加**：各截面信号先在组合层合并（加权或分 sleeve），择时叠加层最后作用于总仓位，不改动选股信号本身。
- **信号来源可追溯**：每个信号记录来源类型（factor / model / event / discretionary_human / discretionary_llm），用于前瞻分池和归因。

## 4. 与 agent loop 和执行边界的关系

| 策略档位 | agent 自主 loop | 验证要求 | 谁批准上线 |
|---|---|---|---|
| 核心选股 | 是（因子 → 模型设计） | L0–L5 完整链路 | 人 |
| 事件驱动 | 事件抽取稳定后成为第二个 loop 对象 | L0–L5，按事件类型累计样本 | 人 |
| 配置层 / 轮动 | 否，agent 提案 | 更严的 L3/L4 门槛，单独 holdout 预算 | 人 |
| 择时叠加 | 否 | 规则 review + 前瞻观察 | 人 |
| 主观判断 | 否 | 前瞻分池追踪 | 人 |

执行边界不变：Agent Trader 中的 agent 只产出信号和提案，下单权限在确定性执行层与人工审批手里（参考 `mmr` 的 proposal 状态机 PENDING → APPROVED → EXECUTED、`OpenAlice` 的决策与执行隔离）。

## 5. 落地顺序

1. 核心选股：指数增强 `StrategySpec` 模板（截面信号 + 基准约束组合 + A 股执行模拟），接入 L0–L5。
2. 择时风控叠加：regime 信任门与回撤控制，随 paper 阶段一起上线。
3. 主观判断对照池：接入人工与 LLM 信号，只进前瞻分池。
4. 事件驱动：先做公告/研报事件抽取与 PIT 时间戳，再作为第二个 loop 对象。
5. 配置层：行业 / ETF 轮动与 ETF 映射。
