# 35 · 个人集中持仓账户：决策类量化任务定义

状态：草案，待人工决定（§8）。日期 2026-10-07。只交付本文，不改代码、配置或预算，不运行 trial，不读取 holdout/fresh。

## 1. 场景与问题

场景来自一个构造的个人账户：2 只科创板股票，单票占比 71%，8 个月内 6 次整仓或半仓切换，没有事先记录的交易理由。复盘时只能拿事后的对照组算账，无法区分“判断错”和“运气差”（见本文 §7）。

把场景抽象为：

| 项 | 设定 |
|---|---|
| 账户 | 5 万–300 万元；2–5 只个股，可含创业板、科创板；单票占比可以很高 |
| 交易规则 | T+1、100 股整手、涨跌停不可成交、卖出印花税、最低佣金 5 元；不能做空 |
| 决策 | 每个复核日，对每只持仓在{持有、减仓、清仓、加仓、换成候选 X}中选一个 |
| 现状 | 决策靠主观判断，没有可检验的事前依据 |

本文要回答的不是“这两只股票该怎么办”，而是：**在这个场景里，什么样的规则能给“动”和“不动”提供定量依据，怎样证明这个依据有用。**

`docs/18` 的 mandate 评价“组合相对基准的超额”。这里评价的是**单个决策的价值**，所以单列一类任务，沿用 mandate 的写法：目标、样本、标签、基线、指标、验收、数据。

## 2. 共同原则

1. **“不动”也是规则的输出，不是默认值。** 每个任务的规则对每只持仓输出动作；输出“持有”必须是因为预测的边际价值低于事先登记的门槛，或者偏离在事先登记的带宽内。门槛本身是预注册参数，计入试验次数。
2. **评价样本不是用户账户。** 一个账户、几笔交易没有统计功效。评价在**合成账户**上做：在 dev 区间的随机日期，从预先定义的股票池里随机抽 2–5 只、按集中权重建仓，生成上万个账户。用户账户只用作端到端用例和前瞻跟踪（§6 P5）。这也让 agent 研究这些任务时不需要接触真实持仓，符合 `agents/integrity.py` 的约束。
3. **基线是一组，不是“拿着不动”一个。** 规则要同时跟三类基线比：
   - 不动：持仓不变；
   - **同频随机**：动作次数、换手与规则相同，但时点和方向随机。这是最关键的零假设，用来检验“规则的时点选择是否比随机好”，而不是“交易是否比不交易好”；
   - 机械规则：固定权重再平衡、单票上限。
   规则只有在成本后显著优于同频随机、且不劣于机械规则时才算有效。
4. **决策价值按动作对照计算。** 对每个决策点，价值 = 规则所选动作在 h 日后的账户财富 − 其他可选动作的账户财富，成本后计。汇总看均值、t 值和分布，不看单笔。
5. **数据区间和记账沿用现有规则。** dev 2012–2022；holdout、fresh 只由 system 读取，读取需人工批准。每个任务单独计 trial 预算与搜索折扣。科创板 2019-07 才开市，dev 内只有约 3.5 年，需要单独报告。

## 3. P1 · 单票下行风险预警（减仓、清仓的依据）

| 项 | 设定 |
|---|---|
| 问题 | 持有某只股票时，未来 h 日相对基准大幅下跌的概率 |
| 样本 | 全 A 非 ST、上市满 60 日，含之后退市的股票（`ashare_all` dev panel，2006–2022，见 §7 PD-5） |
| 输入 | t 日收盘可得的信息：量价、波动、换手、估值、财报红旗（docs/30）、公告事件（docs/31）、两融、解禁 |
| 标签 | h ∈ {20, 60} 交易日；事件 = 相对中证全指收益 ≤ −20%，或持有期最大回撤 ≥ 25%（两种口径预注册，分别报告） |
| 规则 | 预警概率 > p* 时把该持仓降至 w_min；p*、w_min 预注册候选各不超过 3 档 |
| 预测指标 | 相对基准率的 Brier skill score；AUC；最高十分位的事件发生率 / 基准率（lift）；校准曲线；逐年稳定性 |
| 决策指标 | 合成账户上：CVaR(5%) 与最大回撤的改善、平均收益的损失、成本；对同频随机减仓的显著性 |
| dev 验收（草案） | 最高十分位 lift ≥ 2，且至少 70% 年份 lift ≥ 1.5；Brier skill score > 0；合成账户 CVaR(5%) 改善显著优于同频随机（单侧 p ≤ 0.05），平均收益损失不超过 CVaR 改善的一半 |
| 复用 | 因子库、模型层、财报红旗、公告分类 |

为什么先做下行而不是上涨：集中持仓的主要损失来自单票大跌（构造场景里华特气体卖出后又买回，随后跌 44%）；下行事件的基准率和标签更稳定，也不和 A 的超额选股重复。

## 4. P2 · 换仓门槛（换不换的依据）

| 项 | 设定 |
|---|---|
| 问题 | 持有 A、考虑换成 B 时，预测 h 日收益差 r_B − r_A 的分布 |
| 样本 | 合成账户中的每只持仓，配对同池随机抽取的候选 B（以及同行业候选） |
| 标签 | h ∈ {20, 60} 日的收益差，扣除往返成本 |
| 规则 | 预测收益差 > 往返成本 + k × 预测标准误时换仓，否则不动；k 预注册 {0.5, 1, 2} |
| 指标 | 预测收益差的 IC 与校准；被触发换仓的平均净价值及 t 值；对同频随机换仓的显著性 |
| 关键产出 | 经验门槛：预测优势至少多大，换仓的期望净价值才为正。这个数直接回答“大多数换仓值不值得” |
| dev 验收（草案） | 触发换仓的平均净价值 > 0，t ≥ 2，且显著优于同频随机；至少 5 个 dev 年份中为正 |
| 风险 | 与 A 的截面选股高度重叠；若 P2 只是重复 A 的信号，则按 A 的结论处理（A 目前未通过验收） |

## 5. P3 · 仓位与再平衡带（加减到多少、什么时候不动）

| 项 | 设定 |
|---|---|
| 问题 | 不预测收益，只决定权重规则与再平衡带宽 |
| 规则空间 | 权重：等权、波动率倒数、单票上限 c ∈ {20%, 30%, 40%, 不设}；带宽 b ∈ {5, 10, 20} 个百分点，偏离超过 b 才调整；复核频率 {周, 月}。全网格不超过 24 个组合，一次性预注册并全部报告 |
| 样本 | 合成账户；股票池分“中证 800”和“高关注成长池”（创业板、科创板、高换手）两档 |
| 指标 | 期末财富的确定性等价（CRRA，γ ∈ {2, 4}）；P(最大回撤 > 30%)；成本占比 |
| dev 验收（草案） | 选定规则的确定性等价在至少 70% 的年份优于不再平衡；2015、2018、2021–2022 等子区间不出现明显劣化；成本占比 < 年化 0.5% |
| 产出 | 每只持仓的“动/不动”机械依据：越过上限或越过带宽才动，带内不动 |

P3 没有收益预测，搜索空间小，过拟合风险最低，建议最先做。它提供的上限和带宽，也是 P1、P2 规则的执行约束。

## 6. P4、P5

### P4 · 持仓事件响应（公告触发复核）

| 项 | 设定 |
|---|---|
| 问题 | 持仓股发生事件后 h 日的超额收益分布，以及哪些条件会放大效应 |
| 事件（预注册） | 股东减持计划与结果、回购方案与进展、限售解禁、问询函与监管函、业绩预告修正、可转债下修 |
| 条件变量 | 减持比例、股东类型、估值分位、事件前 20 日涨幅 |
| 指标 | CAR 及 t 值（按 C 的口径）；按条件分组的单调性；成本后的决策价值 |
| dev 验收（草案） | 至少一类事件的 CAR60 t ≥ 3，且成本后“事件触发减仓”显著优于同频随机 |
| 复用 | C mandate 的事件研究框架；公告分类（docs/31） |
| 缺口 | dev 区间的历史公告需要回补，需人工审查后运行 |

### P5 · 决策质量度量（评价规则和人的决策）

这是度量工具，不是预测任务；P1–P4 的事后检验和用户账户的复盘都依赖它。

| 项 | 设定 |
|---|---|
| 输入 | 交易日志（`journal` 的 trade / no_action 记录，事前登记理由、论点、预测）、持仓快照、成交记录 |
| 输出 | 每个决策相对其他可选动作的 h 日价值；预测的 Brier 分数与校准；行为统计：处置效应（PGR − PLR）、卖出后 20 日内追回比例、换手成本占收益比例 |
| 结论门槛 | 决策数 ≥ 30 且 bootstrap 置信区间不含 0，才输出“有/无判断力”的结论；之前只报告数字，不下结论 |
| 前瞻 | 每条通过 dev 验收的规则在 fresh 区间开一个**虚拟账户**，按规则每日输出动作并模拟成交，与用户实际账户并排比较。启用需人工逐个批准（同 docs/23） |

## 7. 框架改动与数据缺口

| 编号 | 改动 | 说明 |
|---|---|---|
| PD-1 | 合成账户生成器 | 股票池定义、抽样日期、持仓数、权重分布全部预注册并固定随机种子；生成结果写 artifact |
| PD-2 | 决策回测器 | 按持仓逐个执行动作：T+1、整手、涨跌停不可成交、最低佣金；输出逐决策价值 |

| PD-7 | 虚拟账户 | fresh 区间按规则前瞻记账；看板与真实账户分开显示，快照来源标记为 virtual |

构造场景的复盘（2026-10-07，仅作用例）：按交易记录还原的期末市值与券商导出一致（44,032 元）。事后对照只能说明“这 6 笔交易比不交易少赚约 2.25 万元”，不能说明判断力，因为 6 笔交易没有统计功效、也没有事前依据。这正是 P5 的门槛和 P1–P3 的合成账户要解决的问题。

## 8. 预期，以及对现有能力的取舍

### 8.1 各任务的合理预期

以下是立项前的先验判断，依据是本仓库 dev 实测和常识性的量级估算，不是验收结论。

| 任务 | 合理预期 | 依据 |
|---|---|---|
| P3 仓位与再平衡带 | **几乎一定能产出可用规则**。主要价值是降低大回撤和“单票归零”式损失的概率，确定性等价的提升温和；对收益本身的帮助有限 | 不预测收益，只利用分散化和成本；集中 2–3 只高波动股票时，组合波动与单票接近（构造场景年化波动约 69%） |
| P5 决策质量度量 | 工具价值确定；但对单个账户，**要攒到约 30 个有事前记录的决策才能下结论** | 构造场景 8 个月只有 6 笔交易，没有统计功效 |
| P1 下行预警 | **预测层大概率有效，决策层未必赚钱**。波动和回撤的可预测性远强于收益方向，预期最高十分位 lift 约 1.5–2.5；但按预警减仓，多半是“回撤降低、收益持平或略降”，值不值取决于风险厌恶程度 | 波动聚集是稳健现象；A 的 20 日 RankIC 约 0.07，说明截面信息存在但量级小 |
| P4 事件响应 | **比独立事件组合更有希望**。C 的失败原因是独立组合成本每年约 5%、持仓集中；对已经持有的股票，事件触发的只是一次卖出决策，成本和集中度问题大幅减轻 | C：全 A 业绩超预期 CAR60 高低组差 t = 20，十组单调 0.99 |
| P2 换仓门槛 | **主要产出很可能是“大多数换仓不值得”的定量门槛**，而不是一个能频繁换仓赚钱的规则 | 截面 IC 0.07 时，两只股票 20 日收益差的预测胜率大约只有 52%–55%；科创板个股 20 日收益差的标准差常在 15% 以上，预测优势通常小于预测误差 |

### 8.2 agent 挖因子、回归模型还要不要做

**开放式的 agent 挖因子不应再作为主线。** 实测证据：

- 进化式搜索 400 个 trial，54 个通过 L2，0 个通过 L3：大量相近变体推高了搜索折扣门槛，纯噪声能达到的最大 ICIR 期望值就有 0.78（acceptance-scaling）；
- A 的信号层不是瓶颈：加入 C 的事件分数和 13 个衍生因子后 RankIC 略升，组合信息比率反而全部下降（acceptance-training §3）；
- 人工给定的 21 个因子 trial 只有 3 个通过 L2（D-30）。

调整为：

- **因子库和模型层保留，作为共享基础设施。** P1、P2、P4 的输入就是这些特征。
- **agent 的工作从“自由搜因子”改为“按任务验证预注册假设”。** 例如某类减持公告的条件定义、某条财报红旗规则、某个下行特征。每个假设事先写清定义和验收，逐条记账，不做进化式变体搜索。
- **模型的目标从“排序”改为“校准”。** 决策任务需要的是概率和幅度：减仓要知道大跌概率是多少，换仓要知道收益差的期望和误差，而不只是谁排在前面。模型可以继续用 ridge、logistic、LightGBM，但验收看 Brier、校准曲线和预测区间覆盖率，不只看 RankIC。

### 8.3 是否应该用尽可能多的股票数据

**应该，而且这些任务比 mandate A 更需要。** 理由：

1. 决策按个股计价、在合成账户上评价，股票和年份越多，独立样本越多，统计功效越高；
2. 个人账户常持有的创业板、科创板、小盘股，多数不在中证 800 内；
3. 下行任务最需要的恰恰是极端样本：2008、2015、2018 年的下跌，以及退市股票。`ashare_all` 从 2006 年起、含已退市股票，正好覆盖；
4. 已有证据：`ws_sue` 在全 A 上比中证 800 更强（IC 0.033 对 0.027，成本后超额 3.5% 对 2.2%）；C 的事件信号也是在全 A 上测得的。

但“更多数据”有四个限度，需要在任务设计里处理：

- **有效样本受时间限制。** 同一天的股票受同一市场冲击，截面再宽，独立的市场环境也只有 17 年。验收必须看逐年稳定性和子区间，不能只看合并后的 t 值；
- **幸存者偏差。** 必须包含已退市股票；退市前的停牌、无法卖出要按不可成交处理，否则下行预警会被高估；
- **板块分层。** 科创板 2019-07 才开市，dev 内只有约 3.5 年；微盘股有独立的风格周期（2024 年初踩踏）。结果按主板、创业板、科创板、市值分层报告；
- **可交易性。** 涨跌停、停牌、流动性不足时，规则给出的动作可能无法执行，回测器必须如实处理（PD-2）。
