# 18 · 实际量化任务（mandate）：任务书与框架改动方案

状态：方案，待确认后实现。起草日期 2026-09-28。

## 1. 为什么要从"因子"改成"任务"

到目前为止，AlphaSieve 的终点是"一个因子通过 L0–L3 关卡"。实际的量化产品不是这样评价的：它是一个**有约束的投资组合**，在成本后、相对明确的基准，拿到稳定的超额收益，并且容量够用。实测也说明了这一点：

- 单因子 campaign 通过 L2 的很少（D-30 人工给定的 21 个因子 trial 里只有 3 个），但把因子库合成后，中证 800 的 LightGBM 组合在 dev 样本外做到了信息比率 0.55（acceptance-scaling §4）；
- 因子是否有用，取决于它放进某个具体组合之后的边际贡献，而这取决于基准、约束、调仓频率和成本。

因此引入 **mandate（投资任务）** 作为研究的顶层对象。一个 mandate 写清楚：

| 项 | 含义 |
|---|---|
| 目标 | 例如"相对中证 500 的成本后超额" |
| 标的池与基准 | 可投资的标的、比较的基准（真实指数收益） |
| 约束 | 行业、个股、风格暴露、跟踪误差、换手、成分内比例 |
| 调仓与执行 | 频率、下单价格、交易规则、成本与冲击 |
| 规模假设 | 管理规模，用于容量与冲击成本 |
| 评价与验收 | dev 与 holdout 上的指标和门槛 |
| 数据需求 | 需要哪些数据，缺口怎么补 |

因子挖掘的 campaign 从属于某个 mandate：股票池、预测周期跟着 mandate 走，L2 的边际贡献对照该 mandate 当前的模型计算。

## 2. 通用框架改动（四个任务共用）

| 编号 | 改动 | 说明 |
|---|---|---|
| G-1 | mandate 配置 | `configs/mandates/<id>.yaml`，内容为上表各项；`strategy backtest --mandate <id>` 从配置读取参数，命令行只允许覆盖少数调参项 |
| G-2 | 真实基准 | 超额与跟踪误差一律对真实指数收益（`index_daily`）计算。组合优化需要的基准权重，在没有官方权重时用"PIT 成分 × 流通市值"代理，并在报告里给出代理组合与真实指数的跟踪误差 |
| G-3 | 风险暴露 v0（15 §4 P-6） | 行业、市值、beta、动量、波动率、流动性、估值的截面暴露，作为组合约束；报告逐期主动暴露 |
| G-4 | 容量与冲击 | 按规模假设计算每只股票成交额占比（上限默认 10% ADV），冲击成本用平方根模型（`impact_k` 已在 costs.yaml），报告 1 亿 / 5 亿 / 20 亿规模下的净超额 |
| G-5 | 策略层记账（15 §4 P-5） | 每次策略回测（模型配置、组合参数的一次尝试）写入 trial ledger，层级标记为 `strategy`，按 mandate 计算试验次数与搜索折扣 |
| G-6 | 策略层 holdout（15 §4 P-4） | "是否可以上线"由 mandate 在 holdout 上的结果决定；读取需要人工批准，预算按 mandate 单独计算 |
| G-7 | 标准报告 | 年化净超额、信息比率、跟踪误差、超额最大回撤、逐年超额、换手与成本分解、容量曲线、暴露诊断、参数敏感性（B5）；写 artifact 并上报 RunLab |

## 3. 任务 A：中证 500 指数增强（优先）

**目标**：相对中证 500 指数的成本后超额，跟踪误差受控。这是国内量化最主流的产品形态，也最能直接用上现有的因子库、模型层和组合层。

| 项 | 设定 |
|---|---|
| 标的池 | 中证 500 PIT 成分（月初快照）；第一版 100% 成分内，第二版允许不超过 20% 投向中证 800 以外的非成分股（需确认） |
| 基准 | 中证 500 指数（sh.000905）收益；优化用基准权重为成分 × 流通市值代理 |
| 预测 | 5 日与 20 日两个周期的综合分数；按月滚动训练，训练窗口 5 年 |
| 调仓 | 每 5 个交易日；单次单边换手不超过 15% |
| 约束 | 行业偏离 ±2%；个股主动权重 ±1%；市值暴露 ±0.2 个标准差；beta 0.95–1.05；目标跟踪误差 4%–6% |
| 成本 | costs.yaml b3（佣金、印花税、过户费、滑点）加冲击；规模假设 5 亿 |
| dev 验收（2016–2022 样本外） | 年化净超额 ≥ 6%；信息比率 ≥ 1.0；超额最大回撤 ≤ 8%；7 年中至少 5 年超额为正；5 亿规模下净超额下降不超过 1.5 个百分点 |
| holdout 验收（人工批准后读取） | 净超额 > 0 且信息比率 ≥ 0.5 |
| 数据 | 已有：中证 500 成分、指数日线、全 A 量价、westock 报表、事件；缺口：官方权重（用代理）、PIT 行业（仍是证监会当前快照，写入 warnings） |

实现步骤：

1. A-1 建 `csi500` 股票池与基准代理（G-1、G-2）；
2. A-2 风险暴露 v0、beta 与跟踪误差约束（G-3）；
3. A-3 容量与冲击（G-4）；
4. A-4 策略层 trial 记账与标准报告（G-5、G-7）；
5. A-5 首轮回测：现有因子库加 D-30 新因子，ridge 与 LightGBM 各一版；之后开 mandate 从属的因子 campaign，按边际贡献挖因子。

## 4. 任务 C：业绩超预期漂移（事件驱动）

**目标**：利用财报与业绩快报、预告公布后价格的延迟反应（PEAD）。D-30 的实测支持这个方向：单季净利变化因子 `ws_sue` 在全 A 上 IC 0.033、成本后年化超额 3.5%，是本轮最强的信号。

| 项 | 设定 |
|---|---|
| 事件 | 定期报告（westock 公告日）、业绩快报、业绩预告（BaoStock） |
| 超预期度量 | 季节性随机游走的 SUE（单季净利变化 / 资产或 / 历史波动）；预告增幅中值；快报相对上年同期 |
| 进场与持有 | 公告日之后第一个交易日开盘买入（开盘涨停不买）；持有 20 / 40 / 60 个交易日三档 |
| 组合 | 按超预期度量分十组，做多最高组、等权；股票池为全 A 规则池；基准为中证 500 或全 A 等权 |
| 评价 | 事件时间的累计超额（CAR）曲线按十组展开；日历时间组合的净超额、换手与容量；同一事件的多种度量对比 |
| dev 验收 | 最高组与最低组 CAR(1, 60) 之差 t 值 > 3，十组大致单调；日历时间多头组合年化净超额 ≥ 5% |
| 与 A 的关系 | 合格后作为 A 的一个输入（事件分数进入综合分数），或作为 A 之上的叠加仓位 |

框架改动：事件研究模块（事件窗口形态，11 §4.1 已列但未实现）；事件驱动的日历时间组合回测（持仓按事件进出，不是按固定调仓日）。公告只有日期没有时刻，统一次日开盘进场，偏保守。

## 5. 任务 B：行业 ETF 轮动

**目标**：在 20–30 只行业 / 主题 ETF 间轮动，跑赢这些 ETF 的等权组合。标的少、流动性好、没有印花税，适合个人规模直接落地。

| 项 | 设定 |
|---|---|
| 标的池 | 成交额足够的行业与主题 ETF（上市满一年、日均成交额下限待定）；ETF 上市前用对应的行业指数代替（需在报告中标注） |
| 数据 | westock `kline` 可按日期取 ETF 日线（实测 2017 年起有数据）与指数日线；行业层面的基本面、资金流向由成分股的 westock 数据按行业汇总 |
| 信号 | 行业动量（20–120 日）与反转、行业汇总的盈利修正与 SUE、资金流向、估值分位 |
| 组合 | 持有排名前 3–5 只，等权或按信号加权；每 5 或 10 个交易日调仓 |
| 成本 | 佣金加滑点（2–5 个基点），无印花税 |
| dev 验收 | 相对等权组合年化超额 ≥ 5%；夏普 ≥ 0.8；最大回撤不高于等权组合 |
| 统计注意 | 截面只有二三十个标的，截面 IC 噪声大；以长区间时间序列检验为主，参数网格要小，搜索折扣按 mandate 单独记 |

框架改动：新的资产类型（ETF 原始数据、ETF panel、ETF 与行业的映射）；DSL 的截面算子在小截面上仍可用，但行业内算子没有意义，需要按 mandate 关闭。

## 6. 任务 D：股指期货对冲的市场中性

**目标**：做多 A 的增强组合，同时做空等市值的中证 500 股指期货（IC），获取与市场涨跌无关的超额加基差收益。

| 项 | 设定 |
|---|---|
| 多头 | 任务 A 的组合（依赖 A 先通过 dev 验收） |
| 空头 | IC 主力或次月合约，按多头 beta 调整名义本金；按规则换月 |
| 资金 | 期货保证金约 12%–15%，另留 20%–25% 现金缓冲应对追加保证金 |
| 收益分解 | 多头超额 + 基差收敛（贴水时为正、升水时为负）− 现金拖累 − 交易成本 |
| dev 验收 | 年化净收益 ≥ 5%；年化波动 ≤ 6%；最大回撤 ≤ 5%；夏普 ≥ 1.0 |
| 数据缺口 | westock 期货 K 线不支持历史区间；需要 IC / IF / IM 日线与主力合约映射。Tushare 2000 积分（个人 200 元 / 年）可以覆盖 `fut_daily`、`fut_mapping`，同一档积分也覆盖两融明细与资金流向（见 17） |

框架改动：期货数据 provider；对冲账户模拟（保证金、换月、基差）。

## 7. 顺序

1. A-1 至 A-4（通用框架 G-1 至 G-7 大部分随 A 完成）；
2. A-5 首轮回测，达到 dev 验收或给出差距分析；
3. C（复用 A 的执行与报告，另加事件研究）；
4. B（新资产类型）；
5. D（需先买期货数据，且依赖 A）。

## 8. 需要你确认

1. A 第一版是否只投成分股，第二版再放开 20% 非成分股；
2. 规模假设（默认 5 亿）与 dev 验收门槛是否合适；
3. 是否购买 Tushare 2000 积分（200 元 / 年，公司用途按机构价约 2000 元 / 年），用于 D 的期货数据，以及两融、资金流向的长历史；
4. 策略层 holdout 读取预算：建议每个 mandate 1 次，读取前人工批准。
